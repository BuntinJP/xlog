## Exact public route accounting

Production public surface is 67 routes, while the page-only sitemap is intentionally a single 66-URL `/sitemap.xml`:

- sitemap fixed pages: `/`, `/posts`, `/categories`, `/tags`
- published posts: 17
- category detail: 14
- tag detail: 31
- RSS: `/api/rss.xml` is advertised through `<link rel="alternate">` and `robots.txt` points only to `/sitemap.xml`; RSS is not mixed into the page sitemap

`generateSitemaps` は export しないため、`sitemap-0.xml` / `sitemap-1.xml` の分割は発生しません。Google が無視する `priority` / `changefreq` は出力せず、frontmatter の手動 `updatedAt` だけを正確な `lastmod` として出力します。Drafts are absent from production static params, taxonomy, RSS, and sitemap. Unknown article and taxonomy paths use explicit lookup failure and return 404. `dynamicParams = false` は current Next.js static route で `NoFallbackError` を起こしたため使わず、build 後の unknown post / category / tag を 404 と server log の両方で検証します。

## Intentional corrections

- Legacy RSS accidentally emitted the home `Index` as an 18th item and used file order. New RSS emits exactly 17 published articles newest-first.
- Dirty legacy sitemap leaked one draft and seven draft-only tags. New sitemap is source-derived and excludes all drafts.
- Legacy article route did not hard-block a guessed draft URL. New production route does.
- Legacy used build time for feed/sitemap freshness and Git time for article updates. New output uses only manual `updatedAt`.
- Legacy category detail description called it a tag page. New description says category page.
- Next.js encodes taxonomy URLs according to URL semantics instead of preserving invalid raw spaces/Unicode in XML.
- Home / list / taxonomy use a build-time common large image; each published article gets dedicated build-time Open Graph and Twitter images. Article metadata additionally uses current `article` type with manual publish/update time, author, taxonomy, dynamic image alt, and 1200 x 630 dimensions.
- Article social images use `generateImageMetadata`; the manual `updatedAt` is the image ID, so a material frontmatter update changes the canonical image URL. Only published posts generate images. The old arbitrary query-string `/api/og` generator was removed and now returns 404.
- Legacy catch-all headers also made 404 responses publicly cacheable. New policy gives exact valid page、RSS、sitemap、robots、and fingerprinted SSG image requests explicit browser / Cloudflare / shared CDN / Vercel policy while unknown、draft、migration-only、invalid image requests are `no-store`; public assets outside that allowlist use current Next.js defaults.
- Image conversion never deletes the source. Removal is a separate, manually reviewed filesystem operation outside the converter.
- `lucide-react` experimental optimization was omitted because current Next.js already optimizes it by default.
- Unused math, KaTeX, Twoslash, `feed`, and `next-sitemap` dependencies were not carried forward.

## Migration-only scaffold routes

The migration wiki contains migration policy and internal validation details that are not part of the public blog. Local worktree paths and model-specific prompts remain in repository-only agent/review files. `/docs`, `/api/search`, `/llms.txt`, `/llms-full.txt`, `/llms.mdx/docs/*`, and `/og/docs/*` remain usable in development but return 404 in a production build. They are absent from sitemap and disallowed by robots. Global search stays disabled, matching the legacy site and preventing wiki-only search results on the blog.
