## Comparison boundary

比較元は実際の `https://www.xlog.systems/` response と browser rendering、比較先は `bun run build` 後の `bun run start` です。旧 repository の source、stale `.next`、dirty sitemap を live state の代用にしません。

各 capture で HTTP status、final URL、title、canonical、viewport、above-the-fold、full-page、console error、broken image を記録します。desktop は 1440 x 900、mobile は 390 x 844 を基本とし、必要に応じて 768 x 1024 も追加します。

## Public shell migration rule

- Fumadocs `HomeLayout` は migration wiki には使わず、公開 blog shell からも外します。公開側は legacy の中央寄せ `xlog`、常設 `Posts` / `Categories` / `Tags`、separator、4/6 desktop content width を TypeScript component として維持します。
- 公開 header に dropdown、repository link、theme control、sticky positioning を追加しません。これらは standard Fumadocs navigation の機能であっても、現行公開サイトの情報設計には含まれないためです。
- Fumadocs `DocsLayout` と current provider は development-only migration wiki に残します。blog content pipeline、MDX components、`InlineTOC` も current Fumadocs API を利用します。
- Current Fumadocs `InlineTOC` replaces the legacy custom disclosure. Heading targets and content remain authoritative; exact chevron/padding pixels may differ.
- Dark background, Shippori Mincho body typography, article width, blue links, image constraints, footer text, and floating Buy Me a Coffee control are retained.
- 404 adds an explicit home link and `robots: noindex, nofollow`.
- Draft leakage, RSS Index item, raw invalid sitemap URLs, and category-description typo are correctness fixes and must not be treated as regressions.
- Migration wiki and its LLM/search/OG helpers are development-only and intentionally absent from production.
- Legacy catch-all caching is narrowed to known-valid public routes. Canonical static image URLs include an explicit renderer version and article `updatedAt`; unknown、draft、migration-only、invalid OG responses remain `no-store` so a CDN cannot retain a temporary or attacker-selected 404/image.

## Acceptance

No unexplained missing content, broken image, unreadable contrast, clipped navigation, horizontal page overflow, inaccessible control, metadata regression, or route/status mismatch is acceptable. Public shell の spacing、font size、content width は Fumadocs default への置換を意図的差分として扱わず、live site との一致を必要条件にします。本文内の current Fumadocs primitive に由来する差だけを、ここへ明示した場合に限り許容します。

## 2026-08-03 shell remediation

2026-08-02 QA で許容していた standard `HomeLayout` 差分を撤回しました。公開 shell は legacy structure へ戻し、header label のみ要件に従って Blog から Posts へ変更します。posts / categories / tags index に migration 時に追加されていた可視 page title と余分な max-width / padding も削除し、legacy の content position、taxonomy chip、category ordering、footer 16 px typography を復元します。

canonical CI 後の production local build と live site を同じ browser tab の 1280 x 720 viewport で切り替えて再計測しました。`/` は両方 2049 px、`/posts` は 1502 px、`/categories` は 778 px、`/tags` は 720 px の document height となり、各 route の content width、header position、footer position、horizontal overflow も一致しました。navigation label は要件どおり Blog から Posts へ変更し、幅が増えた分だけ `xl` で 320 px の下限を設け、3 links 間の legacy spacing が潰れないようにしています。

local header は `position: static`、navigation は 20 px、footer 本文は 16 px です。公開 header 内の repository link、button、dropdown/details は全て 0 件で、desktop / mobile とも常設 3 links のままです。390 x 844 では `/`、`/tags`、長文代表記事を確認し、viewport と document scroll width は全て 390 px、console warning / error は 0 件でした。

home MDX heading link の current Fumadocs default blue と line-height 差も public-scope CSS で補正し、live と同じ cream、30 px / 36 px に戻しました。category index は legacy と同じ featured group gap と `備忘録`、`工作` の順を復元し、tags chip と footer は live と同じ寸法で折り返します。長文記事の総高には current `InlineTOC` と anchor control に由来する差が残りますが、本文、画像、導線、可読性、横 overflow に回帰はありません。

tag cloud と article taxonomy badge は link label だけを blue-400、icon、件数、背景を cream / legacy dark surface とします。public shell の default cream color は通常の CSS inheritance で渡し、明示的な link-color utility を一律の `span` override で打ち消しません。

比較中、home sidebar の category / tag が locale-aware order へ変わっていた差分を検出しました。legacy home が使う Unicode code-point order と、taxonomy index が使う post-count + locale tie-break を別々に復元し、英大文字・小文字・日本語を含む順序も live と一致させています。

確認範囲では、説明のない欠落、broken image、読めない contrast、clipped navigation、horizontal overflow、status / metadata regression はありません。deployment、CDN の実 response、analytics ingestion は引き続き別 proof です。
