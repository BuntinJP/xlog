## はじめに

セルフホストできるIdPであるAuthentikというOSSがあることを知りました。

IAM,IdPは、基本的にはGoogle WorkspaceかGitHub、あるいはCloudflare Accessあたりが主に利用されるかと思います。  
はい、安全性、可用性、復旧性、運用コスト、あらゆる面でそれらの方が圧倒的に上です。

ただ、セルフホスト狂の私はOSS代替があれば試さずにはいられません。  
ということで、ホストしてみます。

今回はRHEL10上にPostgreSQLを用意し、PortainerからGitHub上の `compose.yml` を使ってAuthentikを起動してみます。  
DBはコンテナではなく、ホスト側の専用サービスを利用します。

## モチベーション

大前提、ログイン基盤は、GoogleかGitHubで良いのは間違いないです。  
しかし、IdPをセルフホストすると、以下のようなことができます。

- SSOを独自ドメインでホスト可能
- OIDC/SAML/LDAP系の雰囲気を自分の環境で触れる
- Cloudflare AccessやPortainerなど全て集約可能

もちろん、ここで落ちると全部にログイン出来なくなる可能性があります。  
しかし、上には書いていませんが、SSOにGoogle等を利用すると、その利用しているプラットフォームからログアウトするときに、勝手にGoogleもログアウトされるというクソだるい現象が発生することがあります。現にPortainerはそうなります笑

それも完全に塞ぐことができ、自分が実際に利用しているガチのサービスと、お遊びリソースを完全に隔離可能です。  
今回、自分にはそれがかなり魅力的に感じました。

## 構成

構成は以下のようにします。

```text
Client
 │
Nginx
 │ 
Authentik (Docker)
 └── PostgreSQL(RHEL10)
```

Authentik本体はDockerで動かします。  
PostgreSQLはRHEL10側にインストールし、Authentik専用のDB、ロール、接続情報を用意します。

Portainerから作成するため、compose定義はGitHubリポジトリに置きます。  
秘密情報や環境固有の値はGitHubに直接書かず、PortainerのEnvironment variablesから渡します。

## 前提

この記事では以下を前提にします。

- RHEL10
- PortainerでDocker管理
- GitHubで `compose.yml` を管理
- PostgreSQLは外部DBを利用する
- メールサーバーへの認証情報が存在する(オプション)
- `Authentik 2026.2.2` を利用

Authentikはバージョンによって公式composeの形が変わります。  
以前はRedis/Valkeyが必要でしたが、最近のバージョンで不要になりました。  
今回は、`2026.2.2`を利用しました。

## 手順

### PostgreSQLをインストールする

RHEL10側にPostgreSQLをインストールします。

```console
># dnf install -y postgresql-server
># postgresql-setup --initdb
># systemctl enable --now postgresql.service
># systemctl status postgresql.service
```

`postgresql-setup --initdb` は初回だけ実行します。

認証設定を調整するため、 `pg_hba.conf` を確認・編集します。  

```console
># vim /var/lib/pgsql/data/pg_hba.conf
># systemctl reload postgresql.service
```

```text title="pg_hba.conf"
local   all             postgres                                peer
local   all             all                                     scram-sha-256
host    all             all             127.0.0.1/32            scram-sha-256
host    all             all             ::1/128                 scram-sha-256
local   replication     all                                     peer
host    replication     all             127.0.0.1/32            ident
host    replication     all             ::1/128                 ident
```

`postgres`のみ`peer`、それ以外は `scram-sha-256(PW認証)`に設定しました。

### GitHubリポジトリにcompose.ymlを作成する

PortainerからStackとして作成するため、GitHub側に `compose.yml` を置きます。

今回は例として以下のような構成にします。

```text
BuntinJP/Authentik
└── compose.yml
```

`compose.yml` には外部DBの接続先やsecretを直接書かず、Portainerの環境変数から渡します。

```yml title="compose.yml"
x-authentik-common-environment: &authentik-common-environment
  AUTHENTIK_SECRET_KEY: ${AUTHENTIK_SECRET_KEY:?secret key required}
  AUTHENTIK_ERROR_REPORTING__ENABLED: ${AUTHENTIK_ERROR_REPORTING__ENABLED:-false}
  AUTHENTIK_DISABLE_UPDATE_CHECK: ${AUTHENTIK_DISABLE_UPDATE_CHECK:-true}
  AUTHENTIK_DISABLE_STARTUP_ANALYTICS: ${AUTHENTIK_DISABLE_STARTUP_ANALYTICS:-true}

  # PostgreSQL 16 on the Docker host
  AUTHENTIK_POSTGRESQL__HOST: ${PG_HOST:?postgresql host required}
  AUTHENTIK_POSTGRESQL__PORT: ${PG_PORT:?postgresql port required}
  AUTHENTIK_POSTGRESQL__NAME: ${PG_DB:?postgresql database required}
  AUTHENTIK_POSTGRESQL__USER: ${PG_USER:?postgresql user required}
  AUTHENTIK_POSTGRESQL__PASSWORD: ${PG_PASS:?postgresql password required}
  AUTHENTIK_POSTGRESQL__SSLMODE: ${PG_SSLMODE:-disable}

  # Email
  AUTHENTIK_EMAIL__HOST: ${AUTHENTIK_EMAIL__HOST:-}
  AUTHENTIK_EMAIL__PORT: ${AUTHENTIK_EMAIL__PORT:-587}
  AUTHENTIK_EMAIL__USERNAME: ${AUTHENTIK_EMAIL__USERNAME:-}
  AUTHENTIK_EMAIL__PASSWORD: ${AUTHENTIK_EMAIL__PASSWORD:-}
  AUTHENTIK_EMAIL__USE_TLS: ${AUTHENTIK_EMAIL__USE_TLS:-true}
  AUTHENTIK_EMAIL__FROM: ${AUTHENTIK_EMAIL__FROM:-authentik@hogehoge.hogehoge.net}

services:
  server:
    image: ${AUTHENTIK_IMAGE:-ghcr.io/goauthentik/server}:${AUTHENTIK_TAG:-2026.2.2}
    container_name: authentik-server
    command: server
    restart: unless-stopped
    network_mode: host
    environment:
      <<: *authentik-common-environment

      AUTHENTIK_LISTEN__HTTP: ${AUTHENTIK_SERVER_LISTEN_HTTP:-192.168.1.12:10017}
      AUTHENTIK_LISTEN__HTTPS: ${AUTHENTIK_SERVER_LISTEN_HTTPS:-127.0.0.1:10018}
      AUTHENTIK_LISTEN__METRICS: ${AUTHENTIK_SERVER_LISTEN_METRICS:-127.0.0.1:10020}
      AUTHENTIK_LISTEN__DEBUG: ${AUTHENTIK_SERVER_LISTEN_DEBUG:-127.0.0.1:10022}
      AUTHENTIK_LISTEN__DEBUG_PY: ${AUTHENTIK_SERVER_LISTEN_DEBUG_PY:-127.0.0.1:10023}
    shm_size: 512mb
    volumes:
      - data:/data
      - custom_templates:/templates

  worker:
    image: ${AUTHENTIK_IMAGE:-ghcr.io/goauthentik/server}:${AUTHENTIK_TAG:-2026.2.2}
    container_name: authentik-worker
    command: worker
    restart: unless-stopped
    network_mode: host
    user: root
    environment:
      <<: *authentik-common-environment

      AUTHENTIK_LISTEN__HTTP: ${AUTHENTIK_WORKER_LISTEN_HTTP:-127.0.0.1:10019}
      AUTHENTIK_LISTEN__METRICS: ${AUTHENTIK_WORKER_LISTEN_METRICS:-127.0.0.1:10021}
      AUTHENTIK_LISTEN__DEBUG_PY: ${AUTHENTIK_WORKER_LISTEN_DEBUG_PY:-127.0.0.1:10024}
    shm_size: 512mb
    volumes:
      - data:/data
      - certs:/certs
      - custom_templates:/templates
      # - /var/run/docker.sock:/var/run/docker.sock

volumes:
  data:
    driver: local
  certs:
    driver: local
  custom_templates:
    driver: local
```

外部DBに接続する前提なので、`AUTHENTIK_POSTGRESQL__HOST` などをPortainer側から渡します。


Listen先のポートや、PostgreSQLの接続先、メールサーバーの情報などを環境変数で渡しています。

### PortainerからStackを作成する

Portainerにログインし、対象Environmentで `Stacks` から `Add stack` を選択します。  
Build methodは `Repository` にします。

入力例は以下です。

| 項目 | 値 |
| --- | --- |
| Name | `Authentik` |
| Repository URL | `https://github.com/BuntinJP/Authentik` |
| Repository reference | `refs/heads/main` |
| Compose path | `compose.yml` |

Private repositoryの場合は事前に共有シークレットとして、GitHubのPATを登録しておく必要があります。

PortainerのEnvironment variablesに、先ほどの `.env` の内容を入力、もしくはそのままアップロードして反映させます。

CLIですべて完結させる人間だった身としては、コンパネに甘えた人間になってしまったのは恥ずかしいですが、すべてAWSが悪いです(?)。

### Authentikを初期化する

Stackを作成してコンテナが起動したら、ログを確認します。

```console
>$ docker logs -f Authentik-server
>$ docker logs -f Authentik-worker
```

Portainer上からログを見ても良いです。  
マイグレーションが走り、serverとworkerが落ち着けば第一段階は完了です。

設定が反映されているか確認する場合は、workerで `ak dump_config` を実行します。

```console
>$ docker compose run --rm worker ak dump_config
```

Portainer管理の場合は、対象Stackの作業ディレクトリやコンテナexecから確認します。

## 動作確認

最低限、以下を確認します。

- Authentikのログイン画面が表示できる
- `akadmin` でログインできる
- PostgreSQL側に接続が来ている
- workerのタスクが失敗していない
- リバースプロキシ越しのURLでWebSocketやリダイレクトが壊れていない
- 再起動後もログインできる

```console
># systemctl status postgresql.service
># systemctl status valkey.service
>$ docker ps --filter name=Authentik
```

## まとめ

GoogleやGitHubでログインすれば良い。  
それは本当にそうです。

普通に面白いです。だるいですが。
